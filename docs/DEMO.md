## 1. 演示脚本（按顺序走）

### 场景 A：浮窗问库存（验证「数据来自工具，不是 RAG」）

1. 首页**右下角**点「在线客服」→ 浮窗打开
2. 输入：**`无印良品的化妆水有货吗？`**
3. **看三处**：
   - 回答里出现**具体库存数字**（如「有 1000 件」）—— 这个数字来自数据库实时查询
   - 浮窗气泡里出现**商品卡片**（来自 `tool` 事件，不是模型编的）
   - 若展开完整页，右侧面板出现 **`checkStock` 工具调用 + 耗时**

> 💡 **讲解点**：为什么数字可信？因为**语料红线**——向量库里**根本不存价格/库存**，
> 想编也没有素材，只能去查工具。

### 场景 B：追问「这个多少钱」（验证会话记忆）

浮窗里接着问：**`这个多少钱`**（不重复商品名）

**看**：它能接上上文（仍在说那款化妆水）—— 这是会话记忆在起作用
（匿名场景用前端 `conversationId`，不用 session，见 `ARCHITECTURE.md` §6）。

### 场景 C：完整页 + 上下文面板（验证可观测性）

点浮窗里的「**展开完整页**」→ 进入 `/cs`

**看右侧上下文面板的三个区块**：
| 区块 | 内容 | 说明 |
|---|---|---|
| 工具调用 | 调了什么、参数、耗时 | 证明**真查了数据** |
| 引用来源 | 检索到的商品 + 相关度分数 | RAG 命中情况（**只是语义参考**） |
| 质检复核 | 回答是否通过自动质检 | audit 模式下**异步**到达 |

### 场景 D：商品详情页带入上下文（验证 §4.3）

1. 打开商品详情页：**http://localhost:28090/goods/detail/10085**
   （在售商品，库存 1000）
2. 点页面上的「**问客服**」
3. 问：**`这个多少钱`**

**看**：不用说是哪个商品，它知道你在问 10085 —— URL 的 `goodsId` 被带进了会话。

> ⚠️ 注意：`/goods/detail/{id}` 在**未登录**时会被重定向到 `/login`（商城既有行为）；
> 登录后即可正常打开。这一点在 `DEVELOPMENT.md` 里有记录。

### 场景 E：流式输出（验证不是等整段生成）

重新问一个问题，**盯着回答**：

**看**：文字是**一个字一个字出来**的（不是停顿几秒后整段跳出）。
首字延迟低是流式的价值。

### 场景 F：会话记忆跨刷新

**刷新浏览器**（F5）→ 之前的聊天记录**还在**。

> 再进一步：`docker compose restart app` 后刷新，记录**仍在**（存在 MySQL `cs_chat_memory`）。

### 场景 G：限流（验证防刷保护）

快速连续提问 **12 次以上**（可以用浏览器连点，或用 curl 循环）。

**看**：从第 11 次起收到「**这个网络问得太频繁了，请稍后再试**」
（HTTP **429**，不是 200 —— 本项目反复强调不能"200 掩盖错误"）。

**两档限流**：
- 单**会话** 10 次/分钟
- 单 **IP** 60 次/分钟（防"换个 conversationId 继续刷"）

## 2. 用命令行演示（不依赖浏览器）

```bash
CURL="/mnt/c/Windows/System32/curl.exe"     # WSL 里调 Windows 侧 curl
cat > /tmp/body.json <<'EOF'
{"question":"无印良品的化妆水有货吗？","conversationId":"demo-1"}
EOF

# 流式调（-N 关缓冲；必须读完整流才是真实耗时）
"$CURL" -s -N -m 90 -o /tmp/out.txt \
  -w 'HTTP=%{http_code} 读完整流=%{time_total}s\n' \
  -X POST 'http://127.0.0.1:28090/api/cs/chat' \
  -H 'Content-Type: application/json' --data-binary '@D:/tmp/body.json'

# 看事件序列
grep -o 'event:[a-z]*' /tmp/out.txt | sort | uniq -c
```

**期望看到**（顺序可能略有差异，但 `done` **一定在 `review` 之前**）：
```
   1 event:done
   1 event:rag
   1 event:review      ← 终止条件是它，不是 done
   2 event:stage
  12 event:delta       ← 逐字推送
```

## 3. 演示时可能被问到的问题

| 问题 | 回答要点 |
|---|---|
| **库存数字准吗？** | 来自工具实时查询；**语料红线**保证向量库里不存价格/库存 → 想编也没素材 |
| **为什么不做成 iframe？** | iframe 拿不到登录态与商品上下文，样式也难一致；现在是**原生浮窗**，与商城同模板同 CSS 变量 |
| **RAG 和工具的分工？** | RAG 只解决**"找哪个商品"**（语义参考）；**价格/库存/订单状态一律以工具为准**（数据铁律） |
| **流式最难的地方？** | `done` **不是终止事件** —— 质检是异步旁路的，发完 `done` 立即 `complete()` 会让 `review` 抛异常 |
| **换过嵌入模型吗？** | 换过。英文 `all-MiniLM` 的**语义查询**命中率 20% → 中文 `bge-small-zh-v15` **40%**（`RAG-EVAL.md`） |
| **性能优化做过什么？** | 诚实答案：**虚拟线程在本场景没有收益**（瓶颈不在线程），详见 `PERF-M3.md` |
| **上游限流怎么办？** | 自实现线性退避 4s×n（上游 429 明说 `reset after 3s`，1s/2s 跨不过去）+ 兜底话术"当前咨询的人有点多" |
