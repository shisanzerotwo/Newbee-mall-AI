# 使用说明（USER GUIDE）

> 面向**用**这个系统的人：怎么启动、怎么用、遇到问题怎么办。
> 想改代码看 `DEVELOPMENT.md`；想知道为什么这么设计看 `DESIGN.md`。

---

## 1. 这个系统是什么

一套**自带 AI 客服的 Java 电商系统**。

与"商城旁边挂一个客服网站"不同，这里的客服是商城的**原生能力**：

- **右下角浮窗**：全站任意页面都能唤起，不用跳走
- **完整客服页 `/cs`**：左边历史、中间对话、右边**上下文面板**（能看到 AI 查了什么、用了哪个工具、检索到哪些商品）
- **商品详情页「问客服」**：自动带上你正在看的商品，问"这个多少钱"它能答对
- **会话记忆**：刷新页面、甚至重启服务，聊天记录还在

**能回答什么**（都以**真实数据**为准，不编造）：

| 类型 | 例子 |
|---|---|
| 商品咨询 | "无印良品的化妆水有货吗"、"推荐几款耳机" |
| 库存/价格 | "这个多少钱"、"还有货吗"（**数字来自数据库实时查询**） |
| 订单相关 | "我的订单到哪了"（登录后） |
| 模糊问题 | "我想买个送女朋友的" → 会反问引导 |

## 2. 启动（三步）

```bash
cd /mnt/d/GitHub/xiangmu/newbee-mall-ai
docker compose up -d          # 起 MySQL + Redis + 应用
docker compose ps             # 等三个都显示 healthy
```

然后在浏览器打开：**http://localhost:28090**

> 首次启动会**下载中文嵌入模型**（约几十 MB），需要等一两分钟。
> 可以用 `docker compose logs -f app` 看进度。

**验证是否正常**：

```bash
bash ops/smoke.sh http://127.0.0.1:28090     # 期望：通过 16 / 失败 0
```

## 3. 怎么用客服

### 3.1 浮窗（最常用）
商城任意页面**右下角**都有「在线客服」按钮 → 点开就是对话窗口。

### 3.2 完整页 `/cs`
浮窗里点「展开完整页」，或直接访问 `http://localhost:28090/cs`。
右侧**上下文面板**有三类信息：
- **工具调用**：AI 这次查了什么（如 `checkStock(10085)`）+ 耗时
- **引用来源**：检索到的商品片段 + 相关度分数
- **质检复核**：AI 的回答是否通过了自动质检

> 💡 这个面板是"**让 AI 的思考可见**"的设计 —— 你能看出它是不是**真查了数据**，而不是编的。

### 3.3 带上下文提问
从**商品详情页**点「问客服」进入，或浮窗在详情页打开时，会自动带上当前商品。
此时问"**这个多少钱**"、"**有货吗**"能正确解析（不用重复说商品名）。

### 3.4 会话记忆
同一个浏览器里的对话会**自动记住上下文**（存在浏览器的 `conversationId` + 服务端数据库）。
- **刷新页面**：记录还在
- **重启服务**：记录还在
- **换浏览器/清缓存**：会当成新会话（因为 `conversationId` 是浏览器本地生成的）

## 4. 常见问题

### Q1：客服回"当前咨询的人有点多，请稍后再试"
**这是上游模型服务限流了**（免费额度），不是系统故障。
- 系统已经自动**重试 3 次**（每次间隔 4~8 秒），仍然失败才会这样回
- 稍等 1 分钟再问通常就好
- 想彻底解决：换成付费的模型额度（改 `.env` 里的 `CS_MODEL_*`）

### Q2：客服回"这个网络问得太频繁了，请稍后再试"
**触发了限流**（防刷保护）。两档：
- 单**会话**：10 次/分钟
- 单 **IP**：60 次/分钟

等一分钟即可。这是为了保护模型额度不被刷光。

### Q3：客服回"上一条还在回答中，请等它答完再问"
同一会话**同时只能有一个问题在处理**。等上一条答完再问。

### Q4：浮窗按钮没出现
- 确认页面**完全加载**了（刷新一次）
- **登录页/注册页没有浮窗**（正常设计：登录前不需要客服）
- 若整站都没有：看 `docker compose logs app` 有没有报错

### Q5：AI 说的库存/价格会不会是错的？
**不会**。这是本系统的核心设计：
- **价格 / 库存 / 上下架状态一律来自数据库实时查询**（工具调用）
- **RAG 知识库里刻意不存这些字段** —— 从结构上断绝"引用旧价格"
- 你可以在右侧上下文面板看到它**真的调用了哪个工具**

### Q6：为什么回答是"一个字一个字"出来的？
那叫**流式输出**（首字延迟低，不用等整段生成完）。这是特性不是卡顿。

### Q7：容器占用多少资源？能停吗？
```bash
docker compose stop        # 停（数据保留）
docker compose start       # 再开
docker compose down        # 停并删容器（数据卷保留）
docker compose down -v     # ⚠️ 连数据一起删（会重置数据库）
```

## 5. 配置

改 `.env`（首次启动前复制 `.env.example`）：

| 变量 | 说明 | 默认 |
|---|---|---|
| `CS_MODEL_BASE_URL` | 模型网关地址（OpenAI 兼容） | — |
| `CS_MODEL_API_KEY` | 网关密钥 | — |
| `CS_MODEL_NAME` | **必须是真 model id**（如 `agnes/agnes-2.0-flash`），不是显示名 | — |
| `CS_QA_MODE` | 质检模式：`audit`（异步旁路，默认）/ `gate`（同步把关，会拉长响应） | `audit` |
| `CS_RAG_EMBEDDING_MODEL` | 嵌入模型：`bge-zh`（中文，默认）/ `minilm`（英文） | `bge-zh` |
| `CS_LIMIT_RPM` | 单会话每分钟提问上限 | 10 |
| `CS_LIMIT_IP_RPM` | 单 IP 每分钟上限 | 60 |
| `APP_PORT` | 应用宿主端口 | 28089 |

> ⚠️ **换嵌入模型后必须重建索引**（两个模型向量维度不同）：
> 停应用 → `docker exec newbee-mall-redis redis-cli FT.DROPINDEX goods_kb` → 启动应用。
> 细节见 `DEVELOPMENT.md` §5.3。

## 6. 演示路径（3 分钟看完所有能力）

1. **首页** → 点右下角浮窗 → 问「**无印良品的化妆水有货吗**」
   - 观察：回答里的库存数字是**真实数据**；右侧面板出现 `checkStock` 工具调用
2. **继续问「这个多少钱」** → 验证**会话记忆**（不用重复说商品名）
3. 点「**展开完整页**」→ 看三栏布局 + 上下文面板的完整信息（工具/来源/质检）
4. **打开任一商品详情页** → 点「**问客服**」→ 问「**这个多少钱**」
   - 验证：**上下文自动带入**（不用说是哪个商品）
5. **刷新页面** → 聊天记录还在（会话记忆）
6. **快速连问 12 次** → 第 11 次起收到「问得太频繁」（限流生效）

## 7. 边界与诚实说明

| 项 | 说明 |
|---|---|
| **上游模型依赖** | 客服依赖外部模型服务。免费额度会限流（表现为 Q1 的兜底话术）。这是**上游限制**，不是系统缺陷 |
| **中文检索质量** | 已切换中文嵌入模型（`bge-small-zh-v15`）。注意评测口径：**原始 20 条用例里 11 条的类目商品库根本没有**（没有面膜/防晒/眼霜等），所以「合计 8/20 = 40%」被无解题拉低了；只算语料里真有的类目是 **8/9 = 88.9%**。两个数字都如实记录在 `docs/RAG-EVAL.md` §2.3 |
| **虚拟线程** | 已启用，但**实测在本场景没有收益**（瓶颈不在线程）。见 `docs/PERF-M3.md` |
| **限流是单机的** | 单机应用，限流计数在内存里；多实例部署需要换成共享存储 |
| **无鉴权** | 客服接口目前**匿名可达**（只有限流保护）。生产环境需要加登录态与更严格的配额 |
| **`/api/cs/health`** | **默认最小化**：只回 `status` / `db` / `redis`（整体状态 + 依赖可达性；任一不可达 → `status=DEGRADED`，仍返回 200）。用量计数 / 限流配置 / 质检模式属内部信息，需 `CS_HEALTH_DETAIL=true` 才附加，**默认不暴露** |
